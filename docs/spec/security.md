## Prompt Injection in Resume Source {#injection}

**Status**: unresolved — must be fixed in Phase 0 (`spec://cv/phases#phase-0`).

The file `docs/Resume_Dmitrii_Sorokoletov.md` contains a prompt injection payload on lines 45–46.
The payload targets AI-powered ATS systems: when an ATS or recruiter tool feeds the resume to an
LLM, the injected text attempts to override the model's instructions and manipulate its output.

**Action required**: delete lines 45–46 from `docs/Resume_Dmitrii_Sorokoletov.md` before any
deployment, submission, or use of the file as input to any AI tool.

**Why the Astro build does not protect you**: the build process renders Markdown to HTML, which
strips or encodes the payload for display — but the raw `.md` file in the repo and on disk still
contains it. Any tool that reads the file before the build (including `scripts/ats-check.ts`,
`gray-matter`, and any AI assistant reading the file directly) will see the payload.

## AI Presence Disclosure Policy {#ai-disclosure}

### Rationale {#ai-disclosure.rationale}

The use of AI tools in software development is legal and unremarkable in most jurisdictions.
However, in repressive regimes that restrict or criminalise the use of AI, unambiguous indicators
of AI involvement in a repository can expose the author to serious legal risk — including
prosecution, arrest, or imprisonment. Because this repository is public and its git history is
permanent and globally visible, no AI tool may leave traceable evidence of its participation in
commit metadata, source code, or documentation unless the author explicitly approves it for a
specific artefact.

This policy applies to **all AI tools** working in this repository: LLMs, code-completion
assistants, autonomous agents, and any future tooling.

---

### Prohibited {#ai-disclosure.prohibited}

The following are **never permitted** unless the author explicitly approves them for a specific
artefact in writing within the session:

**Git commit metadata**
- `Co-Authored-By:` trailers naming an AI model or AI service
  (e.g. `Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>`,
  `Co-Authored-By: GitHub Copilot <copilot@github.com>`)
- Subject lines or body text stating or implying AI authorship
  (e.g. "Generated by AI", "AI-assisted", "Written with Claude")
- Any emoji or badge conventionally associated with AI generation
  (e.g. `🤖 Generated with Claude Code`)

**Source code**
- Inline comments attributing code to an AI tool
  (e.g. `// Generated by ChatGPT`, `/* AI-assisted */`, `# copilot suggestion`)
- Docstrings or block comments disclosing AI authorship

**User-facing documents**
- README sections, badges, or footnotes stating the project uses AI tooling
- CHANGELOG entries noting that a change was AI-generated
- PR or issue bodies containing AI attribution footers
  (e.g. the default `🤖 Generated with [Claude Code](https://claude.com/claude-code)` footer)
- `package.json` or other manifest fields advertising AI tools

---

### Permitted {#ai-disclosure.permitted}

The following are **always permitted** because they are technical configuration files that instruct
AI tools how to operate — they describe the AI's working environment, not a disclosure of AI
authorship to human readers or external systems:

**Boot and instruction files** (read by AI tools at session start)
- `CLAUDE.md` — Claude Code session instructions
- `AGENTS.md` — OpenAI Codex session instructions
- `.github/copilot-instructions.md` — GitHub Copilot workspace instructions
- `.cursor/rules/` or `.cursorrules` — Cursor rules
- `.windsurfrules` — Windsurf rules
- Any equivalent per-tool configuration file

**AI session state and memory**
- `.claude/` directory and its contents (memory files, project context, hooks)
- Any analogous tool-specific state directory

**Project spec and procedure documents** (internal technical documentation)
- Files in `docs/spec/` — these are architectural specifications, not public disclosures
- Any document that describes how an AI tool should work within the project
  (workflow definitions, prompt templates, ATS check instructions, etc.)
- `SKILL.md` and equivalent skill/agent configuration files

**The key distinction**: a file that tells an AI *how to work* is configuration infrastructure.
A commit message, code comment, or README that tells a *human reader* that AI was involved is a
disclosure. Only the latter is restricted by this policy.

---

### Enforcement {#ai-disclosure.enforcement}

AI tools **must** apply this policy by default at all times, without waiting to be reminded.
Specific exceptions require explicit, per-artefact approval from the author within the active
session. A general statement like "you can mention AI" is not sufficient — the approval must name
the specific artefact (e.g. "add a Co-Authored-By trailer to this commit").

If an AI tool is uncertain whether a particular output would constitute a prohibited disclosure,
it must ask the author before producing the output.
