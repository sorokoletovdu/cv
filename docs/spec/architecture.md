# Architecture {#root}

`spec://cv/architecture`

## Invariants {#invariants}

These constraints are non-negotiable. Any change that violates them requires an explicit ADR update:

- Web (Astro) and PDF (React-PDF) share **data**, never components.
- PDF is generated by **pure Node.js** (`@react-pdf/renderer`). No browser in CI.
- `src/content/resume/resume.md` is the **single source of truth** for all outputs.
- CV layout is **single-column A4** — no tables, no multi-column, no inline icons.
- `src/content/achievements/` is **web-only** — never included in the 1-page PDF.

---

## Overview {#overview}

Transform a static HTML CV into a TypeScript + Astro + Tailwind CSS driven system where:

- **Source of truth** = `src/content/resume/resume.md` (Astro Content Collections, YAML front matter)
- **Web output** = Astro static site → GitHub Pages
- **PDF output** = `@react-pdf/renderer` programmatic PDF (separate visual implementation, same data)
- **ATS check** = Claude API (`@anthropic-ai/sdk`) — ResumeWorded-level feedback, no Docker/Java

### Structural decisions {#structure.decisions}

- `src/content/` is the Astro Content Collections directory. All MD files here are Zod-validated
  via `getCollection()`. Data files moved here from `docs/`.
- `src/pdf/` holds React-PDF components, entirely separate from Astro components. They share data,
  not presentation.
- `docs/` is project-documentation-only (spec files). No source data lives here.
- No `src/data/` directory — data accessed directly via `getCollection()` / `getEntry()`.
- No `scripts/parse-resume.ts` — Zod in `config.ts` handles all parsing at build time.
- No `tailwind.config.mjs` — Tailwind v4 uses CSS `@theme` in `global.css`.
- `astro.config.ts` (not `.mjs`) — TypeScript-first setup.
- `scripts/generate-pdf.tsx` (not `.ts`) — JSX required for React-PDF components.
- No `src/pages/print.astro` — PDF is generated programmatically, not from a browser page render.

## Open-Source Tools Evaluated {#tools}

### OpenResume (`xitanggg/open-resume`) — AGPL-3.0 {#tools.openresume}
- Tech: Next.js 13 + React + TypeScript + Tailwind + Redux + React-PDF
- Cannot be used as a library or CLI — standalone web app only
- **Decision**: Not integrated (AGPL copyleft, no API/CLI surface). Used as design reference for CV
  layout and ATS heuristics only.

### ResumeLM (`olyaiy/resume-lm`) — AGPL-3.0 {#tools.resumelm}
- Tech: Next.js 15 + React 19 + Supabase + React-PDF + Shadcn UI; requires full Docker Compose stack
- **Decision**: Not integrated. Infrastructure cost excessive; same AGPL concern as OpenResume. Used
  as UI/UX reference only.

### Awesome-CV (`posquit0/Awesome-CV`) — LPPL-1.3c {#tools.awesomecv}
- Tech: LaTeX (XeLaTeX) — the layout the user's current resume is based on
- **Decision**: Not integrated (incompatible stack). Used as the **visual specification** for
  React-PDF components. See `spec://cv/design` for extracted design tokens.

### ResumeAtsChecker (`Joseph24x7/ResumeAtsChecker`) — MIT {#tools.resumeatschecker}
- Tech: Spring Boot + Java 17 + Apache OpenNLP; keyword frequency matching only
- **Decision**: Replaced by Claude API. Claude provides semantic feedback (bullet rewrites, scoring,
  section analysis) comparable to ResumeWorded — with no Docker/Java overhead in CI.

### ResumeWorded (`resumeworded.com`) — SaaS, no API {#tools.resumeworded}
- Used by the user to clean up the resume; no API available
- **Decision**: Core features replicated via Claude API in `scripts/ats-check.ts` and
  `ats-check.yml`. Covers ATS score, keyword gaps, weak verbs, missing metrics, bullet rewrites.

## Key Design Decisions {#decisions}

| Decision | Choice | Reason |
|---|---|---|
| PDF generation | `@react-pdf/renderer` | Programmatic, proper font embedding, deterministic, no browser in CI |
| Playwright role | Dev preview only | `playwright open localhost:4321` for visual inspection only |
| Data location | `src/content/` (Astro Collections) | Zod validation at build time, type-safe `getCollection()` |
| Data format | MD + YAML front matter | Version-control friendly, human-readable, Astro native |
| Tailwind version | v4 (`@tailwindcss/vite`) | CSS `@theme` config, no `tailwind.config.js` |
| OpenResume / ResumeLM | Reference only | Both AGPL, web-app-only, no CLI/API |
| ATS checking | Claude API (`@anthropic-ai/sdk`) | ResumeWorded-level feedback without Docker/Java |
| Deployment | GitHub Pages via Actions | Free, fits repo structure |
| PDF + web deploy | Single `deploy-pages.yml` | PDF always in sync with web; stable download URL |
| CV layout | Single-column A4 | ATS-friendly, scannable |
| Package manager | pnpm | Fast, strict, disk-efficient |
