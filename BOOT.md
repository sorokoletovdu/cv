# CV Builder — AI Session Entry Point {#root}

## Session Start Protocol {#start}

**Read in this order before touching any code:**

1. This file (`BOOT.md`) — project context, invariants, REVIEW protocol
2. `WAL.md` — current project state, pending work, what NOT to touch
3. `docs/spec/INDEX.md` — full spec directory (read specific spec files as needed)

Tool-specific files (`CLAUDE.md`, `AGENTS.md`, `.github/copilot-instructions.md`) contain
tool-specific overrides only. All project-wide context lives here.

---

## What This Project Is {#overview}

A TypeScript + Astro CV builder. One Markdown file (`src/content/resume/resume.md`) is the
single source of truth for all outputs: web page (Astro → GitHub Pages), downloadable PDF
(`@react-pdf/renderer`, pure Node.js), and ATS feedback report (Claude API).

Full spec: `spec://cv/architecture#overview`

## Architectural Invariants {#invariants}

These constraints are non-negotiable. Any change that violates them requires an explicit decision
recorded in `WAL.md` and reported to the author:

- Web (Astro) and PDF (React-PDF) share **data**, never components.
- PDF is generated by **pure Node.js** (`@react-pdf/renderer`). No browser in CI.
- `src/content/resume/resume.md` is the **single source of truth** for all outputs.
- CV layout is **single-column A4** — no tables, no multi-column, no inline icons.
- `src/content/achievements/` is **web-only** — never included in the 1-page PDF.
- Package manager is **pnpm** — never npm or yarn.
- TypeScript **strict mode** throughout.
- Tailwind is v4 — no `tailwind.config.js`. CSS-only configuration via `@theme`.

Full spec: `spec://cv/architecture#invariants`

## REVIEW Marker Protocol {#review-protocol}

When you encounter a spec ambiguity, a contradiction between two specs, or a decision you cannot
resolve without author input:

1. **Implement the spec as written** — do not invent alternatives or silently deviate.
2. **Add a REVIEW marker** at the relevant location in the file:
   ```
   <!-- REVIEW: [reason] — spec://cv/relevant#section -->
   ```
3. **Record the item** in `WAL.md` under `## Open REVIEW Items`.
4. **Report to the author** at the end of the session.
5. **Do NOT modify the spec unilaterally** — the author resolves spec conflicts.

If a spec file itself needs updating, note it as a REVIEW item. Never silently update specs
to match your implementation.

---

## Conflict Resolution Hierarchy {#conflict-resolution}

When instructions contradict, the higher authority wins:

1. Explicit author instruction in the current session
2. `docs/spec/` files (individual spec documents)
3. This file (`BOOT.md`)
4. Tool-specific files (`CLAUDE.md`, `AGENTS.md`, `copilot-instructions.md`)

---

## Session Close Procedure {#close}

Before ending a session, update `WAL.md`:

1. Collapse completed items to one-line summaries — details belong in git history, not WAL.
2. List any new REVIEW markers created this session under `## Open REVIEW Items`.
3. Update phase status if any phase changed state.
4. Update `## Next Session Must Read` if something unusual is pending.
5. Keep WAL under 3,000 tokens total. Completed items must not accumulate.
